1 Problem Statement: Bề Mặt Tấn Công Mới của AI Agent Phân Tích Mã Độc
intent/research_pre_validate.md

Khi đưa LLM vào tự động hóa phân tích mã độc, chính Agent trở thành nạn nhân bị tấn công thông qua Indirect Prompt Injection (IPI). Kẻ tấn công biến đổi file mã độc thành phương tiện chuyên chở chỉ thị lừa đảo:

Tấn Công Tĩnh (Static Surface)

Câu lệnh đối kháng giấu trong tệp PE: resources (`.rsrc`), strings data, metadata, version info. Mục tiêu là lừa Agent phân tích ban đầu đổi nhãn kết luận sang BENIGN.

Tấn Công Động (Runtime / RAM Surface)

Mã độc được đóng gói (Themida/VMProtect) che giấu lệnh trên đĩa. Chỉ khi chạy trong Sandbox, mã độc mới giải mã câu lệnh injection vào RAM hoặc bơm vào log qua OutputDebugString, SetWindowText.

A Kiến Trúc 2 Nhánh Dữ Liệu Song Song (Decoupled Pipeline Architecture)
Spec §2 (v1.3.0)

Khắc phục lỗi logic luồng dữ liệu (F02/R03): Tệp PE nhị phân gốc là bất biến (`immutable`). Hệ thống phân tách thành hai nhánh độc lập chạy song song:

1. Nhánh Phát Hiện (Detection Branch)

Quét Promptware

Trích xuất chuỗi tĩnh, memory dump từ PE-sieve, và API debug strings từ TelemetryIngestionAdapter ➔ Bản sao text nạp vào Lớp 0 (Normalization) ➔ Quét qua YARA và Meta Prompt Guard ➔ Sinh ra Adversarial Findings.

Mục tiêu: Bắt toàn bộ dấu hiệu IPI, bảo tồn vị trí byte offset gốc.

2. Nhánh Năng Lực (Capability Branch)

Khử Trùng Hành Vi

Mandiant CAPA phân tích cấu trúc file PE và CAPE sandbox report ➔ Chỉ chiếu (project) các kỹ thuật MITRE ATT&CK theo danh mục cho phép (Allowlist) ➔ Tước bỏ 100% chuỗi tự do (raw text) ➔ Sinh ra Capabilities JSON.

Mục tiêu: Đưa dữ liệu hành vi an toàn cho LLM mà không lộ diện text nguy hiểm.
B 6 Tầng Phòng Thủ Chi Tiết (Layer 0 ➔ Layer 5)
Neurosymbolic Defense
LỚP 0: CHUẨN HÓA

Normalization & De-obfuscation Engine

Loại bỏ Zero-Width characters, phân rã Unicode NFKD, ánh xạ ký tự đồng hình (Confusables), giải mã đệ quy Base64/Hex (Max Depth = 2, max 64KB).

Deterministic Latency: < 2ms
LỚP 1: HEURISTICS

YARA Rules & Telemetry Ingestion Adapter

Bộ luật YARA tĩnh quét chuỗi nhạy cảm; YARA Cuckoo module quét mạng/registry/mutex; Telemetry Adapter trích xuất chuỗi OutputDebugString từ CAPE report.

YARA v4.3.2+ Fixture Verified
LỚP 2: KHỬ TRÙNG

Mandiant CAPA Data Abstraction (Tĩnh & Động)

Rút trích năng lực kỹ thuật sang mã MITRE ATT&CK có cấu trúc, loại bỏ toàn bộ raw text và mã máy tự do trước khi nạp vào LLM Context.

ATT&CK Mapping Attack Surface: -95%
LỚP 3: NGỮ NGHĨA

Meta Prompt Guard-86M (Semantic Classifier)

Mô hình sequence chuyên biệt DeBERTa-v2 phân loại Injection / Jailbreak với độ trễ ≤ 50ms; kết hợp Heuristic phân biệt lệnh shell mã độc vs Promptware.

Neural ML (86M) Threshold: P ≥ 0.75
LỚP 4: QUYẾT ĐỊNH

Decision Policy Gate & Microsoft Spotlighting

Thực thi Ma trận 3 chiều; áp dụng Tag-as-Evidence (bảo tồn phân tích); phân tách message role system tuyệt đối khỏi thẻ <untrusted_malware_telemetry>.

AML.T0051.001 Role Separation
LỚP 5: QUẢN TRỊ

Runtime Execution Rails & Output Schema Governance

Hardcoded Read-Only Dispatcher (cấm shell, write, network egress); Ingress filtering cho dữ liệu trả về từ tool; Guardrails AI kiểm thực schema đầu ra (Re-ask ≥ 2 ➔ Abstain).

AML.T0053 Guard Least Privilege

I Kế Hoạch Triển Khai Thực Nghiệm 5 Modules (Phase 2 Roadmap)
Implementation Plan
MODULE 0 De-obfuscation

Python Normalization Engine

Hiện thực hóa class NormalizationEngine xử lý Unicode NFKD, bóc tách Zero-width regex, tra cứu bảng ký tự đồng hình confusables.txt và giải mã đệ quy Base64/Hex (depth=2, max 64KB).

MODULE 1 Heuristics & Adapter

YARA Engine & Telemetry Ingestion

Biên dịch bộ luật YARA tĩnh; thiết lập máy ảo Sandbox CAPEv2 v2.2; xây dựng class TelemetryIngestionAdapter bóc tách tham số chuỗi từ OutputDebugString đưa vào text stream.

MODULE 2 Neural Classifier

Meta Prompt Guard-86M Microservice

Đóng gói mô hình sequence classification DeBERTa-v2 thành REST API nội bộ với độ trễ tối ưu ≤ 50ms; áp dụng heuristic phân biệt giữa lệnh shell hệ thống và câu lệnh thao túng LLM.

MODULE 3 Sanitization & Policy

CAPA Sanitizer & Policy Gate

Tích hợp Mandiant CAPA JSON parser với cơ chế Allowlist Projection; triển khai hàm evaluate_policy_gate và đóng gói cấu trúc thẻ Spotlighting với message roles riêng biệt.

II Giao Thức Đánh Giá Khoa Học EVAL-SEC-AI-2026-01 (400 Mẫu / 200 Cặp)
Benchmark Protocol

Để cô lập chính xác tác động nhân quả của câu lệnh Promptware, tập benchmark được thiết kế theo Mô hình Ghép Cặp (Paired Design): $\text{Pair} = (S_{\text{clean}}, S_{\text{injected}})$, chỉ khác nhau ở payload tiêm nhiễm nằm trong vùng dữ liệu thuần (`.rsrc`, debug info), đảm bảo mã thực thi không đổi:

NHÓM 1 (100 MẪU)
Clean Benign
File sạch, không có injection. Đo Baseline Accuracy.
NHÓM 2 (100 MẪU)
Benign + Promptware
File sạch bị chèn injection ép nhãn Malicious.
NHÓM 3 (100 MẪU)
Malware Gốc
Mã độc thực tế, không injection. Đo False Positive.
NHÓM 4 (100 MẪU)
Malware + Promptware
Mã độc bị chèn injection ép nhãn Benign. Đo ERR.

4 Cấu Hình Đối Chứng (Baselines):

  • Baseline 1 (Heuristic-only): Chỉ áp dụng tập luật YARA tĩnh.
  • Baseline 2 (Neural-only): Chỉ áp dụng mô hình phân loại ngữ nghĩa Meta Prompt Guard-86M.
  • Proposed Pipeline (Full Neurosymbolic): Toàn bộ 6 tầng bảo vệ từ Lớp 0 đến Lớp 5.
